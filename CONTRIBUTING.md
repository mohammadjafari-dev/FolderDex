# Feedback & issues

FolderDex is a personal, single-maintainer project. Code contributions and pull
requests are not accepted at this time; bug reports and feature suggestions are
welcome through the project's GitHub Issues section. Tell the maintainer what
is broken, what is confusing, or what would make the app better.

**فارسی:** [CONTRIBUTING.fa.md](CONTRIBUTING.fa.md)

## Reporting a bug

[Open an issue](../../issues/new/choose) and pick the **bug report** template
(English or Persian — same fields). The most useful reports include:

- App version (shown in the title bar, e.g. `0.54.0`)
- Windows version (10/11, build number if known)
- The player you use for watch-time tracking (PotPlayer / mpv / VLC / other)
- The drive type where the library lives (internal SSD, internal HDD, external USB)
- Steps to reproduce, what you expected and what actually happened
- The debug log (`folderdex-debug.log` next to the app) if the issue is
  graphical or a crash
- Screenshots, if they show the problem

Before attaching a log or screenshot, remove any personal paths — the app never
sends anything anywhere, but your issue is public.

## Suggesting a feature

[Open an issue](../../issues/new/choose) with the **feature request** template.
Describe the problem you are trying to solve, not only the solution you have in
mind — "I can't find X" is more useful than "add button Y". Ideas are read even
when they can't be implemented right away.

## Roadmap

Short-term work focuses on performance optimization and a Linux port. There are
no dates — see the roadmap in the [README](README.md#roadmap). Feature requests
that fit this direction are naturally more likely to happen.
